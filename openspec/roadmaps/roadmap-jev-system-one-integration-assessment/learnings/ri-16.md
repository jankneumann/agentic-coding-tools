# Learning: ri-16

## Decisions
- **The screen is per-batch, not batched across sessions**: Unlike ri-15's fact-check screen (which batches many findings' questions into one decide() call sharing one packet diff), drain_and_classify already loops over independent (agent_id, session_id) batches with no shared context. The roadmap item's own wording ('ask per session batch') matches this directly: one screen_session() call per batch, at the same point the classifier call used to be unconditional.
- **capability_gap stays exclusively an LLM (stage-two) field**: The screen never produces a capability_gap value -- only a probability, a suggested failure_type, and a suggested severity. A finding's capability_gap text always comes from the existing classifier when it runs, per the parent item's own framing.
- **No production caller exists yet, so this item carries zero live-behavior risk**: Confirmed by a repo-wide search: nothing in agent-coordinator/src/ currently calls drain_and_classify outside test files -- the background task that would drain the buffer on a cadence is not yet wired up. The new stage_one_hint keyword-only parameter on classify_fn's call is therefore purely additive today.
- **The 'recall' acceptance outcome is a wiring test, not a live-calibration claim**: No [live] extra is installed anywhere in this repo (confirmed identically by ri-09/ri-10/ri-11/ri-15), and unlike ri-15's fact-check screen, no recorded production audit-triage batches exist to replay at all. Built a small hand-labeled synthetic fixture from the existing prompt's own documented detection patterns instead, proving the screen's wiring reproduces those labels and recording both numbers for visibility.

## Recommendations
- No production background task currently drains the audit-triage buffer and calls the classifier -- when one is wired up, it should pass stage_one_hint through to a real classify_fn prompt so the seeding this item added actually constrains stage two, not just backfills missing fields after the fact.
