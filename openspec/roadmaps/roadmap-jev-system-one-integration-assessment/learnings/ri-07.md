# Learning: ri-07

## Decisions
- **Adjudication lives inside apply_phase_outcome from the start**: Applied ri-06's own Codex-caught lesson proactively: build_outcome_adjudication_entry is a pure function called directly from apply_phase_outcome's non-replay path -- the real production path every SKILL.md-driven phase transition actually executes -- rather than a Python-level convenience wrapper a real run might never call.
- **Handoff record read from the local-fallback file, not the coordinator**: Grounding found coordination_bridge.try_handoff_read() only supports 'latest handoff for this agent/session', not a lookup by a specific handoff_id. read_local_handoff() reads openspec/changes/<id>/handoffs/<phase-slug>-<n>.json instead -- the one place a specific PhaseRecord is reliably readable -- and degrades to None otherwise.
- **No record_degraded reuse for shadow unavailability**: The roadmap's own scaffolded acceptance outcome named record_degraded for the degraded-decision case; corrected via refine-roadmap before implementation, since that helper marks a different, unrelated acting-decision signal (GATEKEEPER's own). Unavailability here records nothing at all, mirroring ri-06's own precedent.

## Recommendations
- Any future item wanting to promote a judged phase outcome to the acting one should read attribute_disagreements' real-sprint gap first -- there is still no production shadow data to promote against.
- phase_agent._expected_outcomes_for_phase and autopilot.TRANSITIONS remain two independent sources of the same per-phase outcome set; worth unifying in a dedicated follow-up, not bundled into a roadmap item that doesn't need it.
