# Learning: ri-06

## Decisions
- **Shadow call lives inside _phase_gatekeeper, strictly additive**: One line before `return outcome` calls gatekeeper_shadow.shadow_gatekeeper_judgment(state, change_dir, acting_verdict=outcome); the acting verdict's computation is byte-for-byte unchanged, proven by a replay test over two REAL recorded gate_signals fixtures (add-visual-code-explainer and the archived fix-audit-choices-range-ledger-path change) with the shadow judge rigged to disagree.
  - Rejected: Wrapping the whole phase in a decorator/middleware layer -- rejected as more indirection than the one-line insertion needs.
- **Config-sourced thresholds mirror ri-05's review_rules.py precedent**: gatekeeper_shadow.py gained ShadowThresholds + load_shadow_thresholds() (default constants + an optional sidecar JSON), deliberately without a project-override layer -- nothing in the acceptance outcomes asked for one.
- **Shared shadow-record envelope reusable by ri-07**: record_shadow_judgment(state, *, phase, acting_outcome, judged_outcome, judgment) fixes the envelope keys (phase/kind/acting_outcome/judged_outcome) while leaving `judgment`'s inner shape free-form per caller, confirmed safe by reading every existing phase_history consumer (goal_gate.py, runner.py), which all filter by an exact phase-name match.

## Recommendations
- ri-07 should reuse gatekeeper_shadow.record_shadow_judgment for its own Choice(outcome)+Noul(evidence) shadow record rather than inventing a second envelope shape.
- ri-08's promotion decision should read the real disagreement rate from gatekeeper_shadow_report.py once a real shadow period has run -- the default thresholds in this item were never tuned against real data, only chosen to be plausible defaults.
