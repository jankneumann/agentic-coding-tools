# Learning: ri-03

## Decisions
- **dry_run on decide() instead of a hypothetical consuming script**: The scaffold's acceptance outcome presumed a system_one-consuming script already exists to test --dry-run against; none does until ri-09+. Reframed as decide()'s own dry_run parameter -- the enforcement point this item actually owns and can test today.
- **system-one-adapter is a genuine drop-in, confirmed by introspection**: SystemOneAdapterClient.system_one() returns the literal same SystemOneResponse type and shares the same TypeSafeError hierarchy as typesafe_sdk -- decide()'s existing client-handling code needed zero changes to accept it as a test substitute.

## Recommendations
- Every roadmap item's acceptance-outcome text is a hypothesis to verify against the real target, not a fact -- ri-02 and ri-03 both found wrong targets before writing code. When a correction happens mid-implementation, also reconcile the canonical roadmap.yaml text via refine-roadmap, not just plan-findings.md -- ri-02's own contract text drifted for two PRs before a Codex review caught it.
- AST-based guard tests need to reason about scope, not just presence: a check that only looks for an import statement inside a narrow subtree will miss a use that relies on a module-level import -- verify guards with a synthetic positive-and-negative case, not just against the one file that motivated them.
- decide_intent()'s acquisition step is still fallback-only after three items (ri-01/ri-02/ri-03) -- ri-04 onward is where real consumers start migrating and exercising the live path end-to-end for the first time.
