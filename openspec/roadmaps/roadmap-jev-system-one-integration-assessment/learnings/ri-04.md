# Learning: ri-04

## Decisions
- **Plain-dict Noul questions, never typesafe_sdk.Noul**: The real typesafe_sdk.normalize_questions() accepts a plain {"type": "noul", ...} dict as well as a real Noul instance -- confirmed by reading the installed SDK directly. Using the dict form keeps gen-eval compliant with system-one-decisions' own repo-wide guard test (typesafe_sdk imported nowhere outside that package).
- **Kappa measurement deferred; existing-tests-unmodified outcome corrected**: Both scaffolded acceptance outcomes were wrong once grounded against the real code: no 40-item labelled set exists (escalated; user chose to defer), and the rewrite fundamentally changes what drives pass/fail, so the old backend-JSON-mocked tests could not survive unmodified. Both reconciled via refine-roadmap before implementation, not after.
- **Full CI-filtered suite caught a regression the changed test file alone did not**: Two pre-existing test_integration_extended.py cases drove pass/fail through the old backend mocks end-to-end via Evaluator; only running the full 'pytest -m "not e2e and not integration"' suite surfaced them as failures, not the standalone test_semantic_eval.py run.

## Recommendations
- Grounding a roadmap item's scaffolded acceptance outcomes against the real target code and its real test suite -- not just its design docs -- caught two wrong assumptions before any implementation code was written (the kappa dataset and the 'tests pass unmodified' claim). This is now three consecutive items (ri-02, ri-03, ri-04) where the scaffold needed correction; treat every scaffolded acceptance outcome as a hypothesis, always.
- When a shared package (system-one-decisions) gets its first real cross-package consumer, expect packaging gaps invisible to its own test suite (py.typed, extras) to surface via that consumer's own quality gates (mypy --strict here) -- run the consumer's full gate, not just the shared package's.
- system_one_decisions.testing.stub_decide's 'import the module, not the name' caveat is a hard requirement, not a style preference, for any future call-site migration (ri-05 onward): binding via `from system_one_decisions import decide` silently makes every stub_decide call in that consumer's tests a no-op.
