# Learning: ri-17

## Decisions
- **The analyst-archetype rubric dispatch is host-orchestration prose, not Python**: Grounding found digest.py explicitly host-assisted (never calls a model) and an enforced test (TestHostAssistedInvariant) forbidding LLM-SDK imports in skills/supervise/scripts/. The judged scorer went into a new sibling script, rubric_score.py, so digest.py's own docstring stayed literally true and no existing invariant needed to change -- mirroring ri-05/ri-13's 'judgment lives beside X, not inside X' precedent.
- **All-or-nothing degradation, not per-item fallback**: Unlike every other judged item in this roadmap, score_batch discards the WHOLE batch on even one missing/malformed stub-factor answer, rather than degrading that one item individually. This is not a weaker design choice: digest.py's _validate_score_join already rejects any scores document missing a requested stub_key outright (inherited from the sub-agent path's own pre-existing 'missing, partial, invalid, or late output is rejected rather than repaired' policy), so a partial result from the new function would be rejected downstream anyway.
- **Two of four scaffolded acceptance outcomes had no grounding to build from**: No 'Score legend' renderer exists anywhere in the codebase (rendering is host-executed SKILL.md prose, not a Python module) -- resolved by finding digest.py's own justifications dict-comprehension IS the effective renderer, and substituting a legend label there when justification is absent. No recorded manifest + archived analyst output exists to measure an agreement rate from -- the only precedent (ri-06's gatekeeper_shadow_report.py) computes it from live accumulated production data over time, not a static fixture. Shipped compute_agreement() as a tested report function only, explicitly not claiming a real agreement rate, mirroring ri-06/ri-08's build-the-harness-first pattern.
- **This change becomes the new steward of the rubric/digest schema contracts**: test_digest_schemas.py's CHANGE_SCHEMA_DIR pinned a byte-identity check to the original archived change that first defined these schemas. Archived changes are a record and should not be written into (ri-12's identical precedent), so this change added its own contracts/schemas/ copies and repointed CHANGE_SCHEMA_DIR here via change_dir(), preserving the OpenSpec-path-stability guard for this change's own eventual archival.

## Recommendations
- Before implementing a roadmap item whose scaffolded description names a dispatch mechanism ('analyst-archetype rubric dispatch'), verify whether it is actually Python code or host-orchestration prose in a SKILL.md -- this item's target turned out to be entirely prose, changing where the judged code needed to live (a new sibling script) and what 'the fallback' could even mean (SKILL.md dispatch ordering, not a Python function parameter).
- When a roadmap item's acceptance outcome cites a fixture or metric that doesn't exist yet (a 'recorded manifest', an 'archived analyst output'), check whether an earlier item already established the correct pattern for this exact situation -- ri-06's gatekeeper-shadow harness-before-data approach was directly reusable here for ri-17's identical AO4 gap, avoiding both fabricated data and a silently dropped acceptance outcome.
- A per-skill 'host-assisted invariant' test (forbidding LLM-SDK imports in a specific scripts/ directory) is not a signal to avoid system_one_decisions there -- check its exact forbidden-token list first (it did not include system_one_decisions here, matching every other judged skill in this roadmap) before assuming the invariant blocks the item.
