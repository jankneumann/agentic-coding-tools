# Learning: ri-13

## Decisions
- **Noul batching lives beside classify(), not inside classify_finding()**: classify_finding operates on one finding with no visibility into the batch, so _judge_fix_tier_gates is a sibling function called once by classify() after severity filtering. classify_finding gains an optional judged_hint parameter (default None), so every one of the 32 pre-existing tests -- all of which call classify_finding directly -- passes unmodified.
- **No dry_run CLI wiring -- fix-scrub's own --dry-run flag already means something else**: main.py's existing --dry-run flag means 'plan only, apply no fixes' and is unwired to classify() entirely (classify() runs before the dry-run branch exists). _judge_fix_tier_gates still accepts a dry_run kwarg threaded to decide(), matching the shared stubbing convention, but nothing in the CLI wires a flag to it -- reusing the existing flag's name for an unrelated concept would have conflated two meanings in the same module. Documented as design D6, not an oversight.
- **Test-location correction: skills/fix-scrub/tests/, not skills/tests/fix-scrub**: The scaffolded acceptance outcome named skills/tests/fix-scrub, matching AGENTS.md's general convention. But skills/tests/ci_coverage/test_ci_test_coverage.py's own _EXEMPT dict explicitly carves out fix-scrub/tests as covered by the separate test-skills CI job -- a skills/tests/fix-scrub directory would not be reached by any CI job today. New tests went to skills/fix-scrub/tests/test_classify_judgment.py instead, co-located with the pre-existing test_classify.py it extends. Verified by running skills/tests/ci_coverage's own guard suite (131 passed) and openspec validate --strict after the move.

## Recommendations
- Before trusting a roadmap item's acceptance-outcome test-location text, check skills/tests/ci_coverage/test_ci_test_coverage.py's _EXEMPT dict for that skill -- some skills (fix-scrub, bug-scrub) have their own co-located, CI-registered test directory that predates the general skills/tests/<skill-name> convention, and the scaffolder does not know the difference.
- When a roadmap item's target module already has a same-named CLI flag for an unrelated purpose (fix-scrub's --dry-run means 'do not apply fixes', not 'do not call the live judgment API'), do not silently reuse that name -- thread the judgment-layer dry_run as an internal kwarg only and document the non-wiring explicitly, per design D6 here.
