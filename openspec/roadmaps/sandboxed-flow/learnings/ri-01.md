# Learning: ri-01

## Decisions
- **Sandbox auto-allow replaces the reader and interpreter allow rules**: Allow list cut from 100 to 35 entries; an allow rule would approve the unsandboxed retry and undo the read denials
- **The network allowlist is the boundary for outward commands**: excludedCommands matches command text and can be wrapped; github.com is kept off allowedDomains so a wrapped push cannot connect
- **Gate recording needs an explicit ask rule**: It was gated only by absence from the allow list, which auto-allow removes; ask rules added for runner.py and cycle_state.py gate-answer

## Blockers
- The cloud container has no Bash sandbox, so no host behaviour could be exercised → Probe and operator checklist shipped; host verification deferred to the operator

## Deviations
- Plan: Demonstrate credential denial on a sandboxed host → Actual: Tested against a faked filesystem only (reason: No sandbox available where the item was implemented)

## Recommendations
- ri-03 to ri-06: treat text-matched rules as a convenience and put the boundary in filesystem or network policy
- ri-08: gate recording is protected only by text-matched ask rules until the approval-gate service enforces it
- Any item that depends on harness sandbox behaviour needs a host with bubblewrap or Seatbelt; a cloud session can only test configuration
- Run the host checklist in docs/guides/lead-session-sandbox.md before building on ri-01
