# Learning: ri-10

## Decisions
- **The repository's files stay the record; the coordinator holds a whole-snapshot copy per project**: One row per project, replaced on every push; a missing, stale or error-carrying snapshot is listed as degraded
- **The coordinator decides only gates that name an approval request**: Every gate recorded today is routed to the repository with an answer hint; none is decidable through the API
- **The item is left in progress**: Task 5.1 (operator deployment) is open; deploy, smoke, security and E2E did not run

## Blockers
- The cloud container has no container runtime and cannot reach the coordinator's database → Verified by unit tests with a fake database; deployment left as task 5.1
- No gate record carries an approval request id → Decide route built and tested; a later item must write the link when a gate parks

## Deviations
- Plan: Listing verified with snapshots pushed from two repositories → Actual: Verified against test doubles only (reason: Environment limits)

## Recommendations
- A review surface should read GET /gates/pending and show a degraded project as unknown, not empty
- Write an approval request id onto a gate record when it parks, or the decide route stays unused
- Run ApprovalService.get_requests against PostgreSQL before relying on it: its IN filter over a uuid column is untested there
- Confirm the policy operations the routes ask for (request_approval, check_approval) with the operator
- The supervisor mirror's pending_gates is empty while parked merge gates exist; read the collector's output instead
- Real resume_hint text is not a runnable command; do not show it as one
