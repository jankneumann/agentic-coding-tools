# Learning: ri-15

## Decisions
- **Deterministic scorer authoritative; LLM-judge additive (skip-never-fail)**: scorer.py evaluates goal gates against post-run workspace with no LLM; judge.py mirrors gen-eval SemanticBlock (skip when no backend, never overrides deterministic status). Injectable executor makes cross-vendor parity structural (real CLI adapter + FakeExecutor).
- **New package, not a gen-eval extension**: Different unit of test (agent vs service), transport (post-run files/git vs live HTTP/MCP/DB), lifecycle (nightly vs request-path). Reuses gen-eval ExpectBlock/SideEffectsBlock via path dependency.

## Deviations
- Plan: Sub-agent reported 31 passed, but an independent clean-PATH re-run had 1 failure: a correct outcome failed its test-passes goal gate. → Actual: Root-caused to the command-gate scorer shelling bare `python` (resolves via PATH to an interpreter without pytest). Fixed by resolving leading python/python3 to sys.executable, restoring the deterministic-scorer guarantee. Re-verified 31 pass on the previously-failing invocation. (reason: The agent ran tests inside its activated venv where PATH `python` happened to have pytest; the determinism bug was masked. Re-running independently is why the review gate exists.)

## Recommendations
- ri-16 (seed suite + nightly parity) and ri-17 (incident auto-seeding) depend on this; live multi-vendor runs happen on GX10 with real CLIs.
- Confirm [tool.uv.sources] gen-eval path-dep is the intended cross-package linking convention.
