# Learning: ri-05

## Decisions
- **Fail-closed on coordinator-unreachable overrides proceed default**: CoordinatorUnavailable at any notify step -> BLOCKED/COORDINATOR_UNREACHABLE immediately (no sleep), even when default_action=proceed, because unreachable means the human was never consulted (distinct from a denial).
- **Injected clock/sleep/client/audit-sink for deterministic tests**: 30s/5s poll windows run in microseconds; audit sink decoupled from coordinator client so the fail-closed path still audits. New approval-gate capability (enforcement-service vs ri-04 data-contract).

## Recommendations
- Audit sink writes to coordinator MEMORY (try_remember, event_type=approval_gate_decision), not audit_log directly: host skills have no DB handle and there is no external audit-write route. The notify path also yields a server-side audit_log entry via request_approval. In-coordinator deployments can inject an AuditSink calling audit.log_operation.
- push_notification targets /notifications/test (only host-reachable POST found); a dedicated reply-to-approve route is a one-line BridgeCoordinatorClient change.
- ri-06 calls ApprovalGate.evaluate() at real autopilot gate sites and persists loop state on BLOCKED.
