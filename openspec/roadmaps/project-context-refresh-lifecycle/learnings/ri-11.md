# Learning: ri-11

## Decisions
- **The end-to-end rehearsal found what 1552 tests and three gates missed**: Tasks 6.3/6.4 rehearsed a real convergence against a scratch clone with a local bare origin. That is where the defect surfaced: operation_id hashes repository_id, which falls back to the repository DIRECTORY NAME, so two clones compute different ids for the same merged revision and neither finds the other's Context-Refresh-Operation trailer. Measured: reh1 -> pcr-d1f79f036271c8ff, a fresh clone at reh2 -> pcr-2ae8ac65e1dee545, prior.found=false with the trailer sitting in HEAD. Unit tests, the drift gate, openspec --strict, and install --check were all green throughout. A rehearsal against a second checkout is the only apparatus that can express a cross-clone identity bug.
  - Rejected: Fixing the identity rule here -- it is ri-04's canonical provenance.repository_id, inherited byte-for-byte by ri-07 so the ledger cannot split WITHIN a clone. Changing it would alter every committed architecture.provenance.json and make ri-10's drift gate report a producer-identity mismatch repository-wide, reproducing the ri-10 CI failure exactly
  - Rejected: Leaving D4's claim as written -- it said the trailer 'survives a fresh clone', which the rehearsal disproved. Documenting the weaker true claim beats shipping a design that overstates
- **Defense in depth turned a broken check into a safe degradation**: The trailer check (layer 1) failed to fire, but the pre-push compare-and-swap (layer 3) blocked with push_race_lost, exit 2, nothing pushed, and reported the operation resumable with nothing staged discarded. No duplicate reached origin. D5's three layers were not redundancy for its own sake: the layer that failed and the layer that caught it fail for independent reasons, which is what made a latent identity bug survivable rather than corrupting.
- **install.sh --check caught defects no unit test could**: Three separate authors -- two sub-agents and the orchestrator -- wrote SOURCE-CHECKOUT paths into SKILL.md files (skills/.venv/bin/python skills/..., bare `python scripts/cli.py` where bare python does not exist in this repo at all). Every one fails from an installed runtime, where there is no skills/ prefix, and every one is invisible to pytest. install.sh --check found them because it validates the INSTALLED payload rather than the source tree. Baseline discipline mattered: tests/install_sh was 21/21 green on an unmodified main worktree, which turned 'probably ambient noise' into 'definitely mine' in one command.
- **Two near-miss false defects, both from reading the wrong keys**: The convergence record appeared to have manifest: None, seemingly breaking D9's pin-by-digest claim -- but the schema uses flat manifest_path/manifest_sha256, and re-reading correctly showed the digest matching the on-disk manifest exactly. Separately, convergence_commit: None in the staged record is by design and documented: a commit cannot contain its own SHA. Verify the shape before reporting the defect.

## Deviations
- Plan: D4 as written: the commit trailer survives a fresh clone → Actual: The trailer survives a fresh clone OF THE SAME REPOSITORY IDENTITY; identity is directory-derived unless PROJECT_CONTEXT_REPO_ID is set (reason: Measured during the rehearsal. D4 corrected in writing, Step 11.6 instructs operators to set the variable, and two tests pin both the limitation and the escape hatch so a future fix is deliberate rather than accidental.)
- Plan: wp-integration scoped to merging and proof → Actual: Also regenerated contracts-inventory.md and added three missing openspec/contracts/README.md rows (reason: wp-contracts promoting a schema invalidates the DERIVED inventory, which sits outside every package's write_allow. Scope is drawn around files you edit, not files your edit invalidates.)

## Recommendations
- Make the convergence identity intrinsically portable (normalized origin URL, or the root-commit SHA). Spans ri-04, ri-07 and ri-11 -- all three must move together or the ledger splits within a clone.
- Any environment converging one repository from more than one checkout path -- CI plus a developer machine -- must set PROJECT_CONTEXT_REPO_ID.
- Rehearse sync-point work against a scratch clone with a local bare origin. It costs minutes and is the only way to exercise compare-and-swap, push races, and cross-clone identity.
- Promoting a contract invalidates docs/architecture-analysis/contracts-inventory.md. Budget the regen into the integration package.
- Tell work-package agents to REPORT drift-gate output, never investigate it: an agent that cannot fix a class of problem should not be asked to diagnose it. One lost its entire window this way.
