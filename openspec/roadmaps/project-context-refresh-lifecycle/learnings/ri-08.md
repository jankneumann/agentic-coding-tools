# Learning: ri-08

## Decisions
- **The declaration is a hint; changed-file + contract analysis is the detector**: context_impact.surfaces is never treated as evidence of completeness -- a planner can omit it. The authoritative signal is the package's changed files intersected with scope.write_allow minus scope.deny, plus contracts.openapi.files, classified by a glob rule table. This is why the field can stay optional without weakening the gate.
  - Rejected: Trust the declaration and only check it is well-formed (a planner that omits it passes)
  - Rejected: Run the ri-05 check producers to confirm real drift (that is ri-10's job; it would also conflate 'this package changed docs' with 'docs are stale for other reasons')
- **Progressive enforcement keyed on whether the block exists (D3)**: The two acceptance outcomes pull opposite ways -- one demands failure on undeclared impact, the other demands existing packages get a compatibility result -- and every package in the repo lacks the field. Resolution: a package that DECLARES is checked strictly (undeclared -> exit 1); a package that OMITS reports 'unmigrated' with the inferred surfaces spelled out, so migration is a paste. --strict-legacy flips the whole repo to full enforcement in one flag once migrated.
  - Rejected: Single strict mode (would fail all 62 existing files on day one)
  - Rejected: Single advisory mode (satisfies neither acceptance outcome; the gate never bites)
- **Rules live in a reviewable YAML table, not in Python**: context-impact-rules.yaml maps globs to surfaces. Reviewability is the entire point of this gate, so a rule change must be legible in a diff. Loading fails loudly on a missing file or an unknown surface rather than yielding an empty rule set -- a detector that matches nothing would pass every package while appearing to work.
  - Rejected: Hardcoded path prefixes in the detector module
- **index_scopes() resolves the existing scope; it does not add fields**: read_allow/deny already live on `scope`. A parallel copy under context_impact would create two sources of truth that drift. index_scopes(package) returns the resolved {read_allow, deny} pair with deny precedence for ri-12 and the semantic indexer.
  - Rejected: Duplicate read_allow/deny inside the context_impact block
- **The library layer is git-free; the CLI owns the diff**: context_impact.py takes changed_files as a sequence and never shells out, so it unit-tests on literal file lists with no repository -- mirroring how validate_work_packages.py stays git-free. validate_context_impact.py resolves `git diff --name-only <base>...HEAD`, and also accepts repeatable --changed-file so ri-09 can feed it a checkpoint's own file list instead of a git range.
  - Rejected: Fold the check into validate_work_packages.py (breaks its fixture-only contract)
