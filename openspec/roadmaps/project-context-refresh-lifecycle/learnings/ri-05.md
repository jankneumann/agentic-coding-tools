# Learning: ri-05

## Decisions
- **Adapter registry over ri-06 ProducerResult (Approach A)**: Every producer imports and returns the ri-06 ProducerResult; ri-05 adds only registration, fail-closed invocation, and domain adapters. A second offline schema check validates each result against context-refresh-types#/$defs/ProducerResult so ri-07 records results with no translation.
  - Rejected: Standalone ri-05 result contract translated later in ri-07
  - Rejected: Shell commands with unstructured exit codes
- **Content-based freshness, no volatile SHA in generated bytes**: Following ri-04's provenance precedent, generated content depends only on inputs + producer version (byte-identical repeat generation) and never embeds the commit SHA, so committing an artifact does not make it instantly stale. source_revision stays on the ri-06 operation request, not on ProducerResult (D2).
- **Two directory-scoped patterns: marker-file vs tempdir-diff**: Single-file producers (documentation, api.contracts) share a marker-managed generate/check engine; multi-file owners (decisions -> archive_index.py) render into a tempdir and byte-diff the committed tree, making check inherently write-free.
- **openspec.projection is projection-only, offline**: An offline requirement-block merge projects active change deltas onto canonical specs and reports expected artifacts; both modes are read-only because canonical spec merges are cleanup-feature's sync-point job. Avoids the npm CLI (no network in tests).
  - Rejected: Run `openspec archive` in a temp repo copy (needs npx / network)
