# Learning: ri-10

## Decisions
- **Building the drift gate kept catching the gate's own producers**: Five defects blocked a naive gate, and four of them were fail-open: the architecture producer returned fresh unconditionally without checking anything; the decisions emitter embedded absolute archive_root paths and reported 17 phantom stale files (REL=0/ABS=17); ts_analysis.json had recorded 0 modules since 2026-02-23 because TS_SRC_DIR pointed at a `web/` directory that has never existed; and the postgres analyzer errored on every run against a Supabase migrations path removed in the ParadeDB move. Two producers were wrong in OPPOSITE directions -- one reporting drift that did not exist, one reporting freshness it never checked. Measure every producer before designing the gate that consumes them.
  - Rejected: Writing provenance over the stale artifacts to get a green -- binds today's sources to five-month-old output and manufactures exactly the false green D4 exists to remove
  - Rejected: Gating on openspec.projection -- it measures pending archival, not staleness, so it would block every PR with an active change
- **Two defects were invisible to every local verification and surfaced only on the first CI run**: The gate was green locally and red in CI. (1) run_architecture.py built the --python-src-dir/--ts-src-dir/--migrations-dir overrides into a CHILD env dict while build_provenance read os.environ, so provenance recorded fallback roots (src/web/database/migrations) that do not exist -- and compute_input_fingerprint over a missing root hashes a constant, so the input-change arm could never fire. (2) detect_optional_tools() reports whether tree_sitter is importable by the CALLING process; `make architecture-refresh` defaulted to python3 while CI ran the gate under skills/.venv/bin/python, a permanent disagreement no regeneration could settle. Both are differences BETWEEN environments, and a single-environment test cannot express them. This is the argument for the gate being a CI job rather than a local convention.
  - Rejected: Dropping tree-sitter from producer identity -- it genuinely affects treesitter_enrichment.json, so this trades a false positive for a false negative
  - Rejected: Leaving PYTHON ?= python3 and regenerating -- the disagreement is structural, not a stale artifact
- **Fixing the emitter beat fixing the caller, and the user chose it**: decisions.timeline drift traced to emit_decisions_from_archive embedding an absolute archive_root into `Source:` links. The cheap fix was to normalize at the gate; the correct one was to resolve a repository root (nearest ancestor containing a .git ENTRY -- existence, not type, so linked worktrees work) and rewrite source_relpath at emission. Same class of bug still lives in decision_index.py::_cli_main, filed rather than silently widened.
- **Two proposal claims were wrong and had to be corrected in writing**: The proposal asserted docs/decisions/ was stale and that 20 artifacts were stale. Byte-comparison showed the index was fresh and the real count was 2. Corrected in an amendment commit touching proposal, design D9/D10 and tasks 5.2/5.3. A measured-baseline table in the proposal is only worth having if the measurements are re-run rather than estimated.

## Deviations
- Plan: D5 exit-code mapping as originally written → Actual: Unverifiable provenance maps to the drift exit code (2), not the failure code (1) (reason: wp-gate flagged that D5 contradicted D4 and the spec scenario. The spec is normative; the design was corrected to match.)
- Plan: ri-10 scoped to gate construction only → Actual: Absorbed repair of the TypeScript and postgres analyzers (D13) and of provenance root recording plus interpreter binding (D14) (reason: The architecture arm of the gate cannot leave `unverifiable` while the analyzers fail before promotion. Refusing the repair would have shipped a required check that could not pass.)

## Recommendations
- Promote context-drift-gate to a required check via the documented `gh api` call in docs/guides/session-completion.md -- deliberately left as a human step (D11) and still NOT APPLIED.
- A gate that has only ever run in one environment is unverified. Land the CI job before declaring the producer green.
- openspec.projection's informational count tracks the number of active changes and moves on every rebase; do not treat it as a regression.
- decision_index.py::_cli_main carries the same absolute-path defect the emitter had -- fix when next touched.
- ri-11 depends on ri-10 and is now unblocked; ri-12 was already ready.
