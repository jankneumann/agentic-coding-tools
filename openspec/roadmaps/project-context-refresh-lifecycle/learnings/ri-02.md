# Learning: ri-02

## Decisions
- **Bind embedding to one verified source read**: Independent review exposed a transient-mutation race; the adapter now hashes and decodes the same final bytes against the planned Git-blob digest.
- **Make publication verification transaction-decisive**: Attempt storage is locked and reverified under the unexpired lease in the same transaction that renames storage and publishes the manifest.
- **Treat independent re-audit as the completion gate**: One blocker and five high findings were repaired; the re-audit reported no remaining blocker or high issue.

## Blockers
- Live ParadeDB and embedding-provider resources were unavailable → Kept six end-to-end scenarios and migration checks explicitly resource-gated while mandatory deterministic contracts and fixtures passed.
- Pinned CocoIndex App state semantics differed from the initial assumption → Verified that Settings.from_env accepts an LMDB filesystem path, derived state under the proven Git common directory, and never passed the Postgres DSN.

## Deviations
- Plan: Rely on source re-proof after embedding → Actual: Added digest verification at the exact final byte read (reason: A transient edit could be restored before re-proof.)
- Plan: Use preliminary storage verification before publish → Actual: Repeated verification after an access-exclusive lock inside the publication transaction (reason: The previous verify/rename gap admitted post-verification mutation.)

## Recommendations
- ri-03 must read only ready v2 storage for the exact requested revision and return an explicit exact-search fallback otherwise.
- ri-07 should reuse the structured indexing operation/result instead of invoking CocoIndex or Postgres internals directly.
- ri-11 should trigger indexing for the final pushed main SHA and preserve not-configured/degraded evidence without claiming freshness.
