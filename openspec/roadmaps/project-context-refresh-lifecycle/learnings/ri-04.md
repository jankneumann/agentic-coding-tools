# Learning: ri-04

## Decisions
- **Content-based provenance instead of mtime for freshness**: architecture.provenance.json records analyzed SHA, dirty state, producer version, relevant input fingerprint, mode, optional-tool identity, and owned-artifact SHA-256 digests; check mode compares identity + digests and never consults mtime.
  - Rejected: Six-hour graph mtime window (the status quo)
  - Rejected: Architecture-owned Git-local ledger (Approach B)
  - Rejected: Coordinator/Postgres-backed operation service (Approach C)
- **Deterministic clock via SOURCE_DATE_EPOCH across all producers**: Migrated ~10 committed-artifact producers off datetime.now(); the staged runner exports SOURCE_DATE_EPOCH (analyzed commit ts) so two refreshes of one revision are byte-identical and reruns are no-ops. Reused ri-06 atomic.canonical_json_bytes for provenance bytes.
- **Adapter records exactly one canonical ProducerResult; never finalizes**: context_runtime_adapter records producer_id=architecture on the ri-06 (repo,revision) operation, reads it cross-process, and projects it onto legacy RPC status. ri-06's record_producer_result rejects duplicates, so the adapter is idempotent by construction and leaves the whole-operation terminal outcome to ri-07.

## Deviations
- Plan: Branch ri-04 from main → Actual: Stacked ri-04 on openspec/add-durable-context-refresh-records (ri-06, PR #269) because ri-06's project-context-runtime is not yet on main; PR #270 targets the ri-06 branch and retargets main after #269 merges. (reason: ri-04 physically imports ri-06's runtime facade + installed schemas.)
- Plan: Full staging as the default refresh behavior → Actual: Added --staged (stage/validate/promote/provenance, last-known-good on failure) and --check as opt-in paths; the default in-place exec is unchanged to preserve the mocked run_architecture subprocess contract. (reason: Existing runner tests pin the exact default command/env.)

## Recommendations
- ri-07 (orchestrator): consume the architecture ProducerResult via ArchitectureAdapter.read_architecture_result / project_status; call the runtime's finalize only after ALL producers report, not per-producer.
- ri-10 (drift gates): CI should run `make architecture-check` (content-based) and treat exit!=0 as deterministic drift, distinct from external-service degradation.
- ri-11 (convergence): the staged refresh already writes byte-idempotent provenance; a no-op convergence commit yields no architecture diff.
- Producer-version bumps (PRODUCER_VERSION in arch_utils/provenance.py) invalidate freshness deliberately — bump it when analyzer output changes.
