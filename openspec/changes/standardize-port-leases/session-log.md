### Decisions
1. **Coordinator is the lease ledger; the client is the host's eyes** `architectural: port-lease-client` — The coordinator runs in a container with no host socket or compose visibility; bind probes and reconciliation must run client-side and be reported. Keeps the tunnel-exposed surface unchanged.
2. **Persist leases in Postgres, in-memory remains standalone mode** `architectural: agent-coordinator` — A coordinator restart must not forget leases while compose stacks still hold the ports. Write-through to a port_leases table shaped like file_locks; standalone mode unchanged.
3. **Leases belong to agent sessions** `architectural: agent-coordinator` — cleanup_dead_agents releases leases and reports ports_released; heartbeat refreshes; TTL is only a backstop. One staleness definition, not two clocks.
4. **Isolation gate is client-reported and downgrade-only** `architectural: agent-coordinator` — The coordinator does not know a session's environment; the client sends isolation_provided from EnvironmentProfile.detect(). Once true it cannot be lowered. Worktree is not isolation for ports.
5. **Five-port block with ui_port at offset +4** `architectural: agent-coordinator` — Lets the kanban dev server origin be leased and derived into CORS instead of hardcoded 5173.
6. **File backend keeps the coordinator's slot arithmetic** `architectural: port-lease-client` — Both backends compute identical blocks from PORT_ALLOC_* so a host flipping between them cannot overlap; the 15432-25432 range is retired.

### Alternatives Considered
- Host-local file registry as the sole allocator: rejected because Invisible to coordinator and kanban, no session lifetime, leaves coordinator spec text dead, blocks the resource-lease follow-up
- Named .localhost hosts via portless with a minimal DB allocator: rejected because Only HTTP is proxied, containers cannot resolve *.localhost to the host, needs privileged daemon and Node 24, hides collisions rather than removing them; deferred as a possible later layer
- Coordinator reads the host Docker socket for reconciliation: rejected because Widens container privileges and the tunnel surface; contradicts the docker_manager.py fence
- Infer isolation from agents.yaml per agent type: rejected because Describes dispatch policy, not the environment a given session runs in

### Trade-offs
- Accepted Client-side probing and reconciliation complexity over A simpler coordinator-only allocator because Only the client can see host sockets and compose projects
- Accepted A blocked slot may waste capacity for conflict_block_minutes after a false-positive probe over Skipping once and retrying because Prevents two clients alternately rediscovering the same foreign listener
- Accepted GET /ports/status stays unauthenticated and now shows agent ids over Adding auth because Read-only; agent ids are already visible on /agents
