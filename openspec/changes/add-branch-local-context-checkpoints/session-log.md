3. **Trigger derives from ri-08 context_impact, not a new size field** `architectural: skill-workflow` — No required size field exists on work packages; loc_estimate, complexity and package_kind are optional hints that most packages omit. Deriving the trigger from declared context-impact surfaces ties it to the thing being reported on and needs no schema change.
4. **Unmigrated packages are reported as unmigrated, not impact-free** `architectural: skill-workflow` — The ri-08 detector returns None for a missing block and an empty frozenset for an explicit empty list. A missing block is absence of evidence; an empty list is an assertion. Collapsing them would let an unmigrated package appear verified.
5. **Architecture coverage is a merge-base diff, not a slice** `architectural: architecture-refresh` — architecture-provenance.schema.json pins mode to the enum full|quick, so a slice mode would be a contract change. diff_architecture.py already exists standalone and is wired into nothing. Freshness and delta are reported separately because a stale artifact yields a misleading delta.
6. **Checkpoints are report-only within ri-09** `architectural: project-context-refresh-orchestration` — ri-10 owns turning deterministic drift into a CI or merge failure. Shipping a gate here would give ri-10 a gate to rework rather than a signal to consume.

### Alternatives Considered
- Approach A: a third checkpoint() mode inside the ri-07 orchestrator: rejected because A checkpoint claiming the branch HEAD revision's canonical operation would make a later legitimate refresh at that SHA reuse scope-restricted, feature-namespaced results as canonical. Isolation would also rest on the incidental fact that repository_id defaults to the worktree directory name.

### Trade-offs
- Accepted Two code paths that both run producers over A single orchestrator entry point covering all modes because Maintenance cost is payable later; a poisoned immutable ledger entry is not. Mitigated by dispatching through registry.run_producer so the drift surface is orchestration only, not producer semantics.
