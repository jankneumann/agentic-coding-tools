## Phase: Plan (2026-07-26)

**Agent**: claude_code | **Session**: N/A

### Decisions
1. **Gate is a composed Python module with a CLI seam, not CI YAML** — The 'precise artifact list' acceptance outcome is a rendering requirement, and rendering assembled by shell over job output is untestable. A Python module makes the artifact list unit-testable and gives 'make context-drift-gate' as a one-line local reproduction of any CI failure. Also minimises the delta to a contended ci.yml.
2. **Degradation classification is additive; no enum or schema change** — decide_outcome collapses drift, an absent optional owner, and a bad semantic index into one DEGRADED value. OperationState is pinned by the durable operation and manifest schemas and ri-07 D9 makes recorded operations immutable, so widening the enum would break existing records. A new pure classify_degradation function returning four disjoint groups leaves every existing consumer untouched.
3. **openspec.projection drift is informational and never blocks** — Measured: 37 failed validations on unmodified main, tracing to 31 active changes, with the producer's own remediation being 'archive the active change(s)'. Its degraded status means an active change has an unmerged spec delta, which is correct in-flight state, not staleness. A repository always has active changes, so blocking on it would block every PR forever. Written as a normative requirement because the opposite reading is superficially plausible and would look like a reasonable future fix.
4. **Unverifiable architecture provenance blocks; absent tooling degrades** — _default_architecture_producer calls build_provenance (which builds from the working tree) then returns fresh unconditionally, reporting fresh on the same tree where make architecture-check reports PROVENANCE_MISSING and exits 1. Fixed via check_freshness. Missing or malformed provenance maps to drift rather than not-configured, because routing it to not-configured would reintroduce fail-open behaviour through the classifier instead of the producer. A genuinely absent owner stays not-configured.
5. **Semantic index is reported as not-attempted, a value distinct from not-configured** — Acceptance outcome 3 wants explicit external-service degradation reporting, but ri-07 D4 and orchestrator.check deliberately never probe the index so CI stays green without a database. Reporting not-configured would falsely assert that a probe found no configuration. not-attempted makes no currency claim at all, which satisfies 'without treating stale semantic results as current' by construction. No Postgres or embedder is added to CI.
6. **Read-only-ness is asserted by digesting the checkout, not enforced at runtime** — ri-09 D3 states registry.run_producer does not structurally forbid a check-mode write and that ri-10 must assert rather than assume. A runtime guard would change a seam both existing entry points depend on, for a property no current adapter violates. The assertion enumerates list_producers() so future producers are covered, and digests untracked paths too, which is strictly stronger than ri-09's tracked-tree version.
7. **Context-impact validation is diff-scoped and never uses --strict-legacy** — Measured on main: 4 of 70 work-packages.yaml declare a context_impact block; 65 fail under --strict-legacy. Enabling it would make the gate red on arrival. ri-08's progressive enforcement keyed on block existence is deliberate. Also: the validator returns 2 for usage errors, colliding with the drift convention where 2 means drift, so it must be remapped to the gate's 1. Stated honestly that this arm is low-yield today.
8. **Existing staleness is remediated inside this change, in an isolated commit** — 20 artifacts are stale on main, so a blocking gate cannot go green until they are regenerated. They ship as one commit containing only generated output, ordered after the architecture producer fix because fixing fail-open behaviour may surface further drift. Acceptance outcome 4 is only verifiable if there exists a commit at which regeneration produces no diff.
9. **Required-check promotion is documented as a manual step, not claimed as done** — Branch protection requires exactly six contexts and a PR cannot add a seventh. Until an admin applies it, the gate is 'blocking job, not a required context' -- which is precisely how docs/decisions/ drifted, since validate-decision-index has that exact posture. Recorded as a known gap.

### Alternatives Considered
- Approach B -- three separate CI jobs, composed in YAML: rejected because Cheaper (effort S) and granular, but every job inherits the ambiguous DEGRADED exit code, so none can distinguish drift from external degradation. Acceptance outcome 3 would go unmet by construction.
- Approach C -- extend the ri-09 checkpoint into a merge-time gate: rejected because Wrong granularity (checkpoint is per-work-package and needs --change-id/--package-id; a repo-wide PR gate has neither), would modify the 'Checkpoint reporting is advisory' requirement one change after it landed which is what D8 was written to prevent, run_pre_merge_checks never touches the repository, and non-OpenSpec PRs would get no gate.
- A runtime filesystem guard inside registry.run_producer: rejected because Would change the seam every producer and both existing entry points depend on, for a property no current adapter violates. Larger blast radius than the risk warrants; belongs to registry.py's own proposal if ever wanted.
- Blocking the gate on drift not explained by an active change: rejected because More precise than treating all projection drift as informational, but the correlation between projected capabilities and active changes is reasoning cleanup-feature already owns at archive time, and it pushes effort past M.

### Trade-offs
- Accepted A genuinely stale committed spec is invisible to the gate over Correlating projected capabilities against active changes because The correlation duplicates cleanup-feature's archive-time reasoning and exceeds effort M. Recorded as a stated cost, not as solved.
- Accepted Three checks behind one exit code over Three independently red/green CI jobs because The structured report names which check failed and why, and one required context is far easier to promote than three. Granularity is recovered in the report rather than in the job matrix.
- Accepted The context-impact arm catches almost nothing today over Enabling --strict-legacy for real coverage now because 65 of 70 work-package files would fail immediately. Yield rises monotonically as packages migrate; a gate red on arrival is worthless.
- Accepted A larger change diff, mixing generated output with gate code over A separate cleanup change landing first because Avoids an extra PR cycle and a roadmap merge-order dependency. Mitigated by isolating remediation in its own commit touching only generated files.

## Phase: Implementation (2026-07-26)

**Agent**: claude_code | **Session**: N/A

### Decisions
1. **The decisions producer false positive was fixed at the emitter, not the caller** — emit_decisions_from_archive interpolated the archive_root it was given into every rendered Source: link, and the CLI resolves --repo to an absolute path before the producer runs. Measured: relative root 0 artifacts, absolute 17. A producer-side relative-path fix was rejected because it would leave 'make decisions --archive-root <absolute>' able to write machine paths into a committed artifact, and would depend on cwd, which the producer contract does not guarantee. Retiring validate-decision-index was made conditional on this fix: replacing a passing check with a permanently failing one is not a consolidation.
2. **The architecture analyzers were repaired rather than working around them** — make architecture-refresh failed before promotion on every run, so no provenance existed. Writing provenance anyway was rejected: build_provenance records an input_fingerprint over current sources, so committing it over artifacts last regenerated 2026-02-23 would have made check_freshness report fresh -- manufacturing the exact false green D4 exists to eliminate. Three defects fixed: MIGRATIONS_DIR pointed at the removed supabase path, TS_SRC_DIR pointed at a 'web' directory that never existed, and the ts-node runner was incompatible with the resolved typescript 7.x.
3. **A missing configured input root is now a loud skip that writes no artifact** — analyze_typescript.ts exits 0 on a missing directory and writes 'Modules: 0, Components: 0' -- indistinguishable from a repository with no TypeScript. That silence is why an all-zeros ts_analysis.json sat committed for five months. Recording zero modules from a missing directory misreports a configuration error as analysis, which is the same category of defect as the fail-open architecture producer. The validation lives in the skill so every consuming repository gets it; the two path corrections live in the repo-specific Makefile that install.sh does not distribute.
4. **Unverifiable provenance exits 2, not 1** — D5's original table contradicted D4 and the spec scenario 'Missing provenance blocks', which requires the drift exit code. The spec is normative and its behaviour is right: a missing baseline is fixed by regenerating and committing, which is drift remediation, not an apparatus repair. Exit 1 is now reserved for a producer that reached no verdict at all, including a drifted finding that names no artifact -- 'name every stale artifact by path' cannot be satisfied by a finding that names nothing.
5. **Each package's claims were verified by the orchestrator, not accepted on report** — For every package: git worktree list to confirm placement, a diff against the feature branch to confirm scope, and independent reproduction of the RED state. The wp-contracts gate was re-failed by removing the install asset; the wp-lifecycle fix was confirmed by running the producer on the live tree; the wp-emitter fix was confirmed by re-running the relative-vs-absolute comparison. Self-reports about worktree placement are unreliable in this harness.

### Alternatives Considered
- Writing architecture provenance without repairing the analyzers: rejected because It would have bound current sources to five-month-old artifacts and produced a green gate for work never done -- the failure mode the change exists to remove.
- A repository config file for the architecture input roots: rejected because Tidier than Makefile ?= variables and would let the skill validate them, but it would not have prevented this bug: all three config mechanisms fail identically without the missing-root validation. Recorded in D13 as a future option.
- Excluding the architecture arm from the gate to land sooner: rejected because Would have given up a stated acceptance outcome; the operator chose to repair the analyzers instead.
- Treating decisions.timeline drift as real and regenerating docs/decisions/: rejected because The index was provably fresh -- 18 rendered files byte-identical to committed, diff -rq exit 0, and CI's own job passing. Regenerating would have committed machine-specific absolute paths into a correct artifact.

### Trade-offs
- Accepted The change grew well beyond its planned scope over Landing a narrower change with a red or dishonest architecture arm because Two of the five producers were wrong in opposite directions and the architecture pipeline could not run at all. Fixing them was a precondition for the gate meaning anything, not an optional extra.
- Accepted A large generated diff in the remediation commit over Leaving architecture artifacts stale because Isolated into a commit containing only generated output, so the generated noise cannot hide logic changes. Both analyzers ran for the first time since 2026-02-23, so the diff is correspondingly wide.
- Accepted openspec.projection drift is invisible to the gate over Correlating projected capabilities against active changes because That correlation is cleanup-feature's archive-time reasoning. A genuinely stale committed spec is therefore undetected -- recorded in D3 as a stated cost.
