# Contracts

Ri-09 keeps the ri-08 runtime projection contract and updates the lagging OpenAPI document to revision 2: `projection_key`, `/work/reconcile`, and 403/409/422 problem responses become explicit. The adapter maps `LoopState.change_id`, `current_phase`, and `total_iterations` to the existing `projection_key` fields `change_id`, `phase`, and `transition_sequence`. Reserved identity fields are never duplicated in `input_data`, and queue responses are observability-only. The adapter uses the canonical returned task ID with additive coordinator-only issue helpers to maintain its two-label projection-row set; label failure is retryable degradation, not a second source of truth.


The adapter pins `task_type="issue"` and priority 1: the existing `/issues/list` service only returns issue rows, while migration 037 makes `/work/claim` enforce the existing documented issue-row exclusion. Submit mode preserves the existing API and treats only bridge envelopes with `status=error`, `status_code=409`, and `response.detail == reconciliation_required` as signals to call the existing reconcile endpoint; no endpoint version fork is introduced.

Projection rows are exclusively owned by this adapter and carry exactly `change:<change_id>` and `projection:autopilot-phase`. Two additive bridge functions, `try_projection_issue_list` and `try_projection_issue_update`, expose the existing coordinator issue endpoints with the standard no-raise envelope but deliberately bypass GitHub-backend selection. The adapter uses them only for its doubly labelled projection rows and canonical task IDs. Full-label replacement is therefore idempotent and cannot erase labels from ordinary issues. All response fields remain observability outputs and never feed phase state.
