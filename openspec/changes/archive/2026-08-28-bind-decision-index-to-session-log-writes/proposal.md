# Bind the decision index to session-log writes

Architecture layer: **Governance** (drift gate), **Execution** (session-log persistence).

## Why

`skills/session-log/scripts/phase_record.py` states the coupling in its own docstrings —
line 80: session-log decisions "feed the per-capability decision index regenerated by
`make decisions`"; line 165: inline spans are preserved "so the `make decisions`" pass reads
them. And then `write_both()` (line 305) does not regenerate. It is documented as
"Best-effort 3-step persistence: markdown -> sanitize -> coordinator", and there is no
fourth step.

Every OpenSpec change writes a session log. So every change stales `docs/decisions/`, and
the deterministic context drift gate reports it — correctly, as `introduced` drift owned by
the branch — until a human remembers one command.

### Measured, 2026-08-27/28

Six gate firings across three changes, one cause:

| Occasion | Producer | Attribution |
|---|---|---|
| After PR #423's archive pass | `decisions.timeline` | introduced |
| After PR #424's archive pass | `decisions.timeline` | introduced |
| Both planning branches, post-rebase | `decisions.timeline` | introduced |
| `rescope-context-drift-enforcement` session-log commit | `decisions.timeline` | introduced |
| `rescope-architecture-freshness-to-on-demand` session-log commit | `decisions.timeline` | introduced |

The gate was right every time. It named the producer, named the files, and printed
`make decisions`, which fixed it in one command. That is a well-behaved check reporting a
defect nobody had closed.

### Why this is the last one

Three causes made the gate feel like it fired constantly. Two are already fixed:

- **Inherited drift blaming unrelated branches** — `rescope-context-drift-enforcement`
  (#426): the base ref is pinned, findings are attributed `inherited` / `introduced` /
  `indeterminate`, and the blocking verdict is event-aware.
- **Machine-local architecture staleness** — `rescope-architecture-freshness-to-on-demand`
  (#428): the architecture arm is informational and consumers ensure on demand.

This is the third, and unlike the other two it is entirely self-inflicted: the system
invalidates its own derived artifact and then reports itself.

### What this unblocks

The branch-protection promotion (`deferred-tasks.md` in
`archive/2026-08-28-rescope-context-drift-enforcement`) is a judgement about whether the
gate earns being required. That judgement is currently made against a signal dominated by
one unclosed loop. Closing it makes the question answerable on what the gate actually
catches. **This change does not decide the promotion**, and deliberately does not touch it.

## What Changes

**`PhaseRecord.write_both()` gains a fourth best-effort step: regenerate the decision
index.** The write becomes markdown → sanitize → coordinator → **regenerate**.

1. **Always on, no switch.** Measured cost is **0.06s** across 168 changes (58 active, 110
   archived) producing 25 index files. There is no cost argument for a flag, and a flag is
   one more thing to forget — this repository shipped an off-by-default telemetry emitter
   earlier the same session that was correct, tested, and unreachable until it was wired
   twice.
2. **Best-effort, like the three steps beside it.** A regeneration that raises must not lose
   a session log already on disk. It warns and returns, exactly as the sanitize and
   coordinator steps do.
3. **The regeneration is orchestrator-scoped by construction, and that becomes enforced.**
   `write_both()` is called only from orchestrator phase-boundary steps — `plan-feature`
   11.5, `implement-feature` 7.5, `cleanup-feature`, `iterate-on-plan`,
   `iterate-on-implementation`, `validate-feature`, `session-log`. No work-package worker
   prompt calls it. Today that is convention; this change pins it with a test, because the
   moment a worker calls `write_both()` it writes `docs/decisions/**` outside its
   `write_allow` and trips the scope checker.
4. **The gate keeps checking.** This removes a cause, not the check. A hand-edited session
   log, a manual archive move, or any other path that stales the index must still be caught
   and must still block. A scenario asserts it.

**Not BREAKING.** The signature is unchanged, no caller is modified, and every existing
behaviour of the three prior steps is preserved. The only observable difference is that
`docs/decisions/` is current after a write instead of stale.

### Decided at discovery

- **Scope conflict: retired, not resolved by compromise.** The concern was that regenerating
  writes `docs/decisions/**`, outside every package's `write_allow`. Verified: `write_both()`
  has no worker call sites, so the conflict is latent rather than actual. Rather than widen
  a scope declaration or exempt derived paths from a checker that caught three real defects
  this session, the invariant is pinned by a test.
- **`cleanup-feature` already regenerates** after `openspec archive`, and keeps doing so.
  Archiving stales the index by moving a directory, which is a different trigger from
  writing a session log. Both remain.

## Approaches Considered

### Selected Approach

**Approach A — a fourth step inside `write_both()`**, selected at Gate 1 on 2026-08-28.
Regeneration is always on with no switch (measured 0.06s), best-effort like the three steps
beside it, and orchestrator-scoped by construction — an invariant this change pins with a
test rather than leaving as convention. Approaches B, C and D are retained below for the
record.

### Approach A — A fourth step inside `write_both()` — **Recommended**

Regeneration becomes part of the persistence sequence that already owns the write.

**Pros**: the coupling is closed where it is created, so it cannot be forgotten by a caller;
one edit covers all seven orchestrator skills; the best-effort contract already exists and
is documented; no call site changes.
**Cons**: `phase_record.py` gains a dependency on the index generator
(`explore-feature/scripts/archive_index.py`), which must degrade cleanly when absent.
**Effort**: S

### Approach B — A wrapper at each orchestrator call site

Each of the seven skills calls regeneration after `write_both()`.

**Pros**: no new dependency inside `phase_record.py`; each skill stays explicit about what
it writes.
**Cons**: seven edits instead of one, and seven future skills that must remember. This is
the failure mode being fixed, relocated — the current bug is precisely that regeneration
lives in a step callers must remember.
**Effort**: M

### Approach C — A git pre-commit hook

Regenerate whenever a commit touches a session log.

**Pros**: catches hand-edits too, which Approach A does not.
**Cons**: hooks are not installed in CI, in cloud harnesses, or in a fresh clone, so the
guarantee holds only where someone ran the installer — and the gate exists because
convention-only enforcement failed before (issue #157). Hand-edits stay the gate's job.
**Effort**: M

### Approach D — Extend the dependabot remediation servo to all pull requests

Let CI regenerate and push instead of preventing the drift.

**Pros**: reuses shipped machinery; fixes every cause at once, including hand-edits.
**Cons**: widens the repository's only `contents: write` grant beyond the dependabot
confinement an entire work package was spent establishing, and it repairs the artifact after
the fact rather than never staling it. Worth revisiting on its own merits; not this change.
**Effort**: M

## Acceptance criterion

A branch whose only change is a session-log write, made through the normal
`PhaseRecord.write_both()` path, runs `make context-drift-gate` and does **not** see
`decisions.timeline` in `blocking_drift`.
