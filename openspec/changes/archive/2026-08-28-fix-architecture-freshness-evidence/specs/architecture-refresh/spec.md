# architecture-refresh — delta

## MODIFIED Requirements

### Requirement: Architecture Provenance Evidence

Every successful architecture refresh MUST write
`docs/architecture-analysis/architecture.provenance.json` conforming to the published
architecture provenance schema. It SHALL identify the repository, exact analyzed Git
SHA, dirty state, architecture producer/version, mode, relevant input fingerprint,
deterministic timestamp, optional-tool identity, validation outcome, and sorted owned
artifacts with SHA-256 digests.

Every recorded artifact SHALL declare a `tier` of `committed` or `local-cache`.
`committed` means the artifact's bytes are tracked in version control and a clean
checkout is expected to contain them. `local-cache` means the artifact is generated by
the pipeline but deliberately not tracked, so a clean checkout is expected *not* to
contain it. The tier is recorded rather than inferred: a reader of provenance MUST be
able to distinguish an artifact that is intentionally absent from one that failed to
generate, without consulting the repository's ignore rules.

<!-- Scenario ID: architecture-refresh.1 -->
#### Scenario: Clean revision produces complete provenance

- **WHEN** a full architecture refresh succeeds in a clean Git worktree
- **THEN** provenance SHALL record exact `HEAD`, `worktree_dirty=false`, producer
  version, input fingerprint, and every required artifact digest

<!-- Scenario ID: architecture-refresh.2 -->
#### Scenario: Dirty relevant input is represented truthfully

- **WHEN** relevant tracked or untracked input differs from `HEAD`
- **THEN** provenance SHALL retain `HEAD` as the analyzed revision
- **AND** SHALL set `worktree_dirty=true`
- **AND** the fingerprint SHALL describe working-tree bytes

<!-- Scenario ID: architecture-refresh.16 -->
#### Scenario: Every recorded artifact declares its tier

- **WHEN** a refresh records an artifact in provenance
- **THEN** the entry SHALL carry `tier` of exactly `committed` or `local-cache`
- **AND** an entry with a missing or unrecognized `tier` SHALL make provenance
  schema-invalid rather than defaulting to either tier

### Requirement: Content-Based Architecture Freshness

Architecture freshness MUST be determined from schema-valid provenance, current
relevant-input identity, producer identity, mode, and owned-artifact digests. Mtimes
and elapsed wall-clock age MUST NOT decide freshness.

An artifact's `tier` SHALL decide what its absence means. A missing `committed`
artifact is drift. A missing `local-cache` artifact is the expected state of a clean
checkout and SHALL NOT be drift. Presence is judged the same way for both tiers: when a
`local-cache` artifact *is* on disk its digest SHALL still be verified, so a stale cache
is reported rather than trusted.

<!-- Scenario ID: architecture-refresh.3 -->
#### Scenario: Mtime-only change stays fresh

- **WHEN** identity and bytes are unchanged but artifact mtimes change
- **THEN** check mode SHALL report `fresh`
- **AND** affected-test selection SHALL accept the graph

<!-- Scenario ID: architecture-refresh.3b -->
#### Scenario: Artifact-only convergence commit does not self-invalidate

- **WHEN** a later commit changes only provenance-owned architecture artifacts
- **THEN** check mode SHALL report `fresh` when relevant fingerprints agree
- **AND** SHALL retain the analyzed source commit as provenance

<!-- Scenario ID: architecture-refresh.4 -->
#### Scenario: Relevant input change is stale immediately

- **WHEN** a relevant source/config file is added, removed, renamed, or modified
- **THEN** check mode SHALL report `INPUT_FINGERPRINT_MISMATCH`
- **AND** a recent graph mtime SHALL NOT override it

<!-- Scenario ID: architecture-refresh.5 -->
#### Scenario: Architecture producer change invalidates freshness

- **WHEN** architecture producer or output-affecting tool identity changes
- **THEN** check mode SHALL report stale and name producer identity as the cause

<!-- Scenario ID: architecture-refresh.6 -->
#### Scenario: Invalid provenance fails closed

- **WHEN** provenance is missing, malformed, or schema-invalid
- **THEN** check mode SHALL never report fresh
- **AND** affected-test selection SHALL use its full-suite fallback

<!-- Scenario ID: architecture-refresh.17 -->
#### Scenario: Absent local-cache artifact is not drift

- **WHEN** a clean checkout contains every `committed` artifact and no `local-cache`
  artifact
- **THEN** check mode SHALL report `fresh`
- **AND** SHALL NOT report `ARTIFACT_MISSING` for any `local-cache` entry

<!-- Scenario ID: architecture-refresh.18 -->
#### Scenario: Present local-cache artifact is still digest-verified

- **WHEN** a `local-cache` artifact is present on disk with bytes that differ from its
  recorded digest
- **THEN** check mode SHALL report `ARTIFACT_DIGEST_MISMATCH` naming that path
- **AND** the verdict SHALL be stale

<!-- Scenario ID: architecture-refresh.19 -->
#### Scenario: Provenance from an earlier schema version fails closed

- **WHEN** committed provenance declares a schema version this producer no longer emits
- **THEN** check mode SHALL report stale with a reason naming the schema version
- **AND** SHALL NOT report the mismatch as artifact drift, which would misdirect the
  reader to regenerate individual files rather than the record

### Requirement: Additive Architecture RPC Status Facade

The RPC SHALL project canonical operation/architecture-result evidence onto existing
method names and status strings. Deprecated `max_age_hours` and `graph_mtime` MAY
remain but MUST NOT affect freshness.

The facade's own default construction path SHALL resolve the repository, so that the
content-based projection is what a caller reaches without configuring anything. A
deprecated mtime-and-age probe MAY remain reachable for a caller that has no
repository — a source export with no `.git` — but SHALL NOT be selected merely because
the entry point omitted to resolve one. Artifact paths the facade reads SHALL be
resolved against the resolved repository rather than the process working directory.

<!-- Scenario ID: architecture-refresh.14 -->
#### Scenario: Existing caller receives additive response

- **WHEN** a caller invokes `is_graph_stale(max_age_hours=6)`
- **THEN** legacy response fields SHALL remain
- **AND** source SHA, producer version, fingerprint, provenance path, shared operation
  ID, and freshness reason SHALL be added

<!-- Scenario ID: architecture-refresh.15 -->
#### Scenario: Invalid shared evidence degrades safely

- **WHEN** the coordinator client encounters transport failure, malformed provenance,
  or a corrupt/schema-incompatible shared operation
- **THEN** it SHALL return `RefreshClientUnavailable` rather than raise
- **AND** merge-train full-suite fallback SHALL remain available

<!-- Scenario ID: architecture-refresh.20 -->
#### Scenario: Default entry point is provenance-backed

- **WHEN** a caller reaches the facade through its default construction path inside a
  Git repository
- **THEN** the response `reason` SHALL NOT be `mtime`
- **AND** source revision, producer version, input fingerprint, and provenance path
  SHALL be populated rather than null

<!-- Scenario ID: architecture-refresh.21 -->
#### Scenario: Elapsed time alone never flips the default entry point to stale

- **WHEN** relevant inputs, producer identity, and artifact digests are unchanged
- **AND** more wall-clock time elapses than any configured age threshold
- **THEN** the default entry point SHALL continue to report not stale

<!-- Scenario ID: architecture-refresh.22 -->
#### Scenario: Freshness does not depend on the working directory

- **WHEN** the facade is reached from a working directory other than the repository root
- **THEN** it SHALL resolve artifact paths against the repository
- **AND** SHALL return the same verdict it returns from the repository root
