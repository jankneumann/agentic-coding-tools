### Alternatives Considered
- Runtime auto-discovery (implement the existing spec literally): rejected because Fails open: a broken CLI or unreachable service yields an empty declared set and a green gate. Would encode as architecture the exact defect PR #277 removed three times. Also cannot detect excess by construction, since anything the implementation exposes becomes definitionally correct.
- Annotated hand-authored descriptors with an operation_id cross-link plus a lint: rejected because Fixes coverage keying cheaply but leaves ~114 entries hand-maintained, does not address flag-only naming or excess detection, and the operation_id annotation needs the same drift guard as a descriptor with none of the benefit.

### Trade-offs
- Accepted Writing and maintaining a CLI binding spec (cli-contract.schema.json) over Mechanical derivation of flags from OpenAPI parameters because An operation's (path, query, body) does not map mechanically onto argv - arrays as repeated flags, --no-x booleans, stdin for body, env for auth. The binding spec is what makes flags nameable, and flag-only nameability is what currently lets ACA ri-06's coverage gate pass for free.
- Accepted Dual-path descriptor loading during a deprecation window over A breaking v2 with a hard cutover because ACA, agentic-assistant and the coordinator all consume the current shape, and a hard cutover blocks on a coordinator OpenAPI contract that does not exist yet.
- Accepted Changing the meaning of unevaluated_interfaces, which ACA ri-06 asserts on over Leaving per-surface string keying in place because Mitigated by keeping the flat field populated from the operation model (D6) and by DOWNSTREAM.md. Note ri-06's gate is already vacuous for flag-only CLIs today, independent of this change.
