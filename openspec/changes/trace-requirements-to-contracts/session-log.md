### Decisions
1. **D13: one opt-in switch per direction; the exclusions file is the reverse switch** — Three analysts independently found the opt-in unit contradictory (per contract vs per capability vs per file), and the per-capability reading made task 5.2's staging infeasible (122 requirements to triage before locks.yaml could opt in). Forward and reverse are different claims with different owners; keying reverse on the exclusions file means the switch cannot be flipped without doing the triage it certifies, and it gives requirement-side exclusions the home the schema lacked.
2. **Reject the gatekeeper's proposed wp-model write_allow widening** — Deeper analysis showed interface-descriptor.schema.json is only reachable from InterfaceDescriptor; the traceability field belongs on archetype-only models with an absent default, keeping both CI byte-identity gates green with no new write scope. 3. **Add a skill-workflow spec delta rather than leaving skill wiring unspecced** — skill-workflow already specs Contract Ref hand-population and (per the ri-08 precedent) is where workflow-blocking gates are specced; changing that behavior without a delta would be exactly the unspecced-surface problem this change attacks. 4. **Fail-closed scope inputs for the change-scoped gate** — An unresolvable merge base or missing change id must error, never resolve to an empty touched set — a blocking gate that evaluates nothing while exiting zero is the defect class the change exists to eliminate, and this repo has already been bitten by the shallow-clone variant.
5. **Skip vendor review inside this skill run** — The autopilot orchestrator runs PLAN_REVIEW (multi-vendor parallel-review-plan) immediately after PLAN_ITERATE; dispatching the same review twice doubles cost for no information. Stated openly per the no-silent-fallback rule.

- Split wp-gate into core and scope packages: rejected because Raising the timeout to 240min plus an explicit test-file mapping addresses the sizing finding with far less churn than re-cutting the package DAG.
