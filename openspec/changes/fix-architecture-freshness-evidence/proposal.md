# Fix architecture freshness evidence

## Why

Architecture freshness is specified as content-based, and the content-based engine
exists, is tested, and is correct. Nothing in production reaches it.

`get_server()` (`skills/refresh-architecture/scripts/rpc_server.py:394`) constructs
`RefreshServer(graph_path=...)` with no `repo_root`. `rpc_server.py:252` treats a
`None` `repo_root` as "use the deprecated graph-mtime probe", so every RPC caller —
including the merge train at `agent-coordinator/src/merge_train_service.py:220` —
gets a freshness verdict decided by file mtime against a 6-hour threshold
(`GRAPH_STALE_MAX_AGE_HOURS`, `merge_train_service.py:63`).

Observed on a clean tree at `main`:

```
$ run_architecture.py --check
  {"status": "fresh", "reasons": []}

$ rpc_server is_graph_stale '{"max_age_hours": 6}'
  {"stale": false, "graph_mtime": "2026-08-26T11:43:38+00:00", "reason": "mtime",
   "source_revision": null, "input_fingerprint": null, "provenance_path": null,
   "operation_id": null}
```

Every provenance field is `null`. Six hours later the same unchanged tree reports
`stale: true`, and the merge train drops to a full-suite run
(`merge_train_service.py:234`) for no reason. This contradicts two ratified
requirements in `openspec/specs/architecture-refresh/spec.md`:

- **Content-Based Architecture Freshness** — "Mtimes and elapsed wall-clock age MUST
  NOT decide freshness."
- **Additive Architecture RPC Status Facade** — "Deprecated `max_age_hours` and
  `graph_mtime` MAY remain but MUST NOT affect freshness."

Two adjacent costs make the same evidence expensive to carry. `docs/architecture-analysis/`
commits ~3.7 MB of generated JSON with no merge driver, so concurrent branches that
both regenerate conflict, rebase, and regenerate again. Over the last 301 commits,
**22** touched architecture inputs (`agent-coordinator/src`, `apps`, migrations) while
**27** touched the generated outputs — the artifacts are rewritten more often than
their inputs change.

## What Changes

1. **Ground the RPC probe in provenance.** `get_server()` resolves a `repo_root`
   (env override, then `git rev-parse --show-toplevel`) and resolves the graph path
   against it, so the production entry point uses the content-based path.
   `DEFAULT_GRAPH_PATH` (`rpc_server.py:58`) is currently relative, which makes the
   same probe answer `stale: true, graph_mtime: null` from any working directory
   other than the repository root.

2. **Declare the heavy generated JSON unmergeable.** `.gitattributes` gains
   `merge=binary` for `architecture.graph.json`, `architecture.diagnostics.json`,
   `treesitter_enrichment.json`, and `parallel_zones.json`, following the `uv.lock`
   precedent (commit `2c31a75e`). A conflict in a resolver output is always resolved
   by regenerating, never by merging lines; binary merge forces that.

3. **Give provenance a typed artifact tier, and demote three artifacts to it.**
   Each recorded artifact gains a `tier` of `committed` or `local-cache`.
   Freshness treats an absent `local-cache` artifact as expected rather than as
   `ARTIFACT_MISSING`, but still verifies its digest when the file *is* present, so a
   stale local cache remains detectable. `committed` keeps today's behavior exactly.

   `treesitter_enrichment.json` (1.25 MB), `parallel_zones.json` (520 KB), and
   `python_analysis.json` (991 KB) — **2.76 MB**, ~75% of the heavy set — move to
   `local-cache`, are untracked, and are added to `.gitignore`. All three remain
   generated by the pipeline; only the commit stops.

   The consumer scan found no hard reader for any of the three:
   `treesitter_enrichment.json` is read by `insights/pattern_reporter.py:160` and
   `insights/comment_linker.py:162`, both of which log and skip when absent;
   `parallel_zones.json` by `reports/architecture_report.py:1140` plus agent-prose
   references in `plan-feature/SKILL.md:175` and `explore-feature/SKILL.md:147`;
   `python_analysis.json` has no reader outside `refresh-architecture/scripts` at all,
   its only other mention being the pipeline diagram at
   `refresh-architecture/SKILL.md:65`.

**Deliberately out of scope** — `architecture.graph.json` and
`architecture.diagnostics.json` stay `committed`. The graph is read from *git history*
by `checkpoint.py:339` (`git show <merge-base>:...`) and by the `architecture-diff`
target feeding `validate-feature`'s new-cycle gate, and it is `required=True`. The
`tier` field this change introduces is what would make moving it tractable later.

## Approaches Considered

### Approach 2: Typed artifact tiers in provenance — **SELECTED**

Add a `tier` field (`committed` | `local-cache`) to the provenance artifact schema.
Freshness ignores a missing `local-cache` entry but still digests it when present.
Wire `repo_root` through the existing `RefreshServer` constructor parameter, and add
the `.gitattributes` entries.

**Pros**
- The uncommitted set stays *recorded and auditable* rather than erased. A reader of
  `architecture.provenance.json` can tell that a file is deliberately local-only, not
  that it was never generated.
- A stale local cache remains detectable, because the digest is still checked whenever
  the file is present.
- Extends cleanly if `architecture.graph.json` is ever moved out of the commit — the
  vocabulary for that decision exists after this change rather than being invented then.
- Makes the change's central claim expressible in the spec: freshness distinguishes
  "evidence that must be committed" from "cache that may be absent".

**Cons**
- `PROVENANCE_SCHEMA_VERSION` (`provenance.py:83`) bumps 1 → 2, and the published
  schema's `schema_version` is `const: 1`, so the constant must move with it.
- Ripples to `openspec/schemas/architecture-provenance.schema.json` and its contract
  test `skills/tests/refresh-architecture-contracts/test_architecture_provenance_contract.py`.
- Artifact items are `additionalProperties: false`, so no consumer can ignore the new
  field by accident — every reader of the published schema must be updated in step.
- Provenance recorded before this change becomes schema-invalid and therefore fails
  closed until one `make architecture-refresh` runs. This is the designed behavior for
  a producer-identity change, but it is a real transient.

**Effort**: M

### Approaches not selected

- **Approach 1: Minimal repair in place** — drop the three artifacts from
  `_OWNED_TOP_LEVEL` with no schema change. Smallest diff (S) and independently
  revertable, but "deliberately uncommitted" becomes invisible in provenance and a
  stale local cache is undetectable. Rejected because the audit trail is the point:
  erasing the artifacts from the record trades a durable distinction for a code comment.
- **Approach 3: Delete the legacy mtime path outright** — make `repo_root` required and
  remove the mtime branch (S). Rejected because the spec says the deprecated fields
  **MAY** remain, `test_rpc_server.py:314-317` pins legacy mode deliberately, and it
  removes the degraded path for a source export with no `.git` that
  `input_enumeration_strategy` (`provenance.py:313`) still supports.

## Non-Functional Requirements

| Attribute | Metric | Target | Verifying phase |
|---|---|---|---|
| Correctness | `is_graph_stale` freshness reason at the production entry point | never `"mtime"` when the repository resolves | Unit (Tier 1) |
| Correctness | Elapsed wall-clock time with unchanged inputs | never flips `fresh` to `stale` | Unit (Tier 1) |
| Correctness | Absent `local-cache` artifact on a clean clone | never reported as `ARTIFACT_MISSING` | Unit (Tier 1) |
| Correctness | Present-but-modified `local-cache` artifact | still reported as `ARTIFACT_DIGEST_MISMATCH` | Unit (Tier 1) |
| Repository weight | Bytes of generated JSON tracked under `docs/architecture-analysis/` | reduced by ≥ 2.76 MB | Static (Tier 0) |
| Compatibility | `make context-drift-gate` on a clean clone after the change | exit 0 | Integration (Tier 2) |
| Compatibility | Provenance recorded at `schema_version: 1` | fails closed with a named schema reason, never silently fresh | Unit (Tier 1) |

## Impact

**Affected specs**
- `architecture-refresh` → `specs/architecture-refresh/spec.md` (MODIFIED ×3)

**Affected contracts**
- `openspec/schemas/architecture-provenance.schema.json` — `schema_version` `const` 1 → 2;
  artifact items gain a required `tier` enum

**Affected code**
- `skills/refresh-architecture/scripts/rpc_server.py` — `get_server()`, `DEFAULT_GRAPH_PATH`
- `skills/refresh-architecture/scripts/arch_utils/provenance.py` —
  `_OWNED_TOP_LEVEL`, `PRODUCER_VERSION`, `PROVENANCE_SCHEMA_VERSION`,
  `build_provenance`, `check_freshness`, `validate_provenance`
- `.gitattributes`, `.gitignore`
- `docs/architecture-analysis/` — three files untracked

**Affected architecture layers** — Execution (analyzer pipeline) and Coordination
(merge-train test selection consumes the RPC verdict).

**Mirror requirement** — `gate-drift-with-mirrors-hooks-and-blocking-ci` will add a CI
job failing on drift between `skills/` and the `.claude/skills/` / `.agents/skills/`
mirrors. Every code edit here is under `skills/`, so `install.sh` must be re-run before
push.

**Not breaking for callers.** No public interface is removed and no behavior a caller
depends on changes. Provenance recorded before this change is invalidated by the
schema-version bump; that is the designed signal for a producer-identity change and it
resolves with one `make architecture-refresh` committed alongside.
