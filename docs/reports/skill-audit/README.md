# Skill audit reports

Generated by `/skill-audit` (`skills/skill-audit/`). Each audit writes two
files per skill:

| File | Contents |
|---|---|
| `<skill>-<date>.md` | Layer histogram, dispatch profile, tier failure table, ranked findings, proposed lean `SKILL.md` and `references/procedure.md` outlines, freshness stamp |
| `<skill>-findings.json` | The findings ledger, valid against `skill-audit-findings.schema.json` |

`--propose` additionally writes `<skill>-candidate-work.json`, whose entries
validate against `openspec/schemas/candidate-work.schema.json` and feed
`/prioritize-proposals`.

These files are committed evidence, not scratch output. A report is the
record of what the skill corpus looked like against one roster; keep older
reports so drift across roster rotations stays readable.

## When a report is stale

Every report stamps `archetypes_sha256`, the roster's `reviewed` dates, the
evidence window, and `generated_at`. `skill_audit.py <skill> --check-freshness`
exits `1` when that hash no longer matches
`agent-coordinator/archetypes.yaml`, which is the signal to re-audit. The
`skill-audit-freshness` CI job runs the `--all` form and annotates without
blocking, because a stale audit is a prompt to re-run the audit, not a defect
in the change under review.

## Reading a finding

Each finding names the layer it applies to, the section, the evidence, and
exactly one remediation. A `contract`-layer finding can never carry `delete`;
the schema and a guard in `findings.py` both enforce that, because contract
sections are what other agents depend on. Teaching that cites a
repository-specific path or command is downgraded to `keep`, with the citing
token recorded in `evidence.repo_specific_tokens`.
