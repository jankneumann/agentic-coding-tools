### Root causes found

**Five dependabot failures were one bug.** #443–#447 each failed
`docker-smoke-import` identically. The image builds with `uv sync --locked`,
which asserts `uv.lock` matches `pyproject.toml`; dependabot raises the pin and
never regenerates the lockfile. `rerun-checks` could not have fixed any of them.
They also all edited the same file, so merging one would have staled the other
four. Consolidated into #452 with one regenerated lockfile, verified with the
exact image command. Cause filed as #454 — the next pip bump reproduces it.

**`main` was red before this pass**, on `documentation.inventory` blocking drift
at `ef5a9146`. Not caused by any PR: a previous pass merged without converging.
Fixed here — see Context Convergence.

### Vendor Review Findings

- **#448**: 1 unresolved P2 from `chatgpt-codex-connector` — label values were
  concatenated raw into a PostgREST query string joined on `&`, so a label
  containing `&` or `#` truncated the filter. Confirmed real by test before
  fixing: `list_issues(labels=["research & design"])` sent `labels=cs.{research`.
  Fixed on the branch and merged with the fix. Only `%`, `&`, `#`, `+` are
  encoded, so `change:foo` stays readable and the PR's own existing assertions
  still hold; `%` is escaped first, which is what makes the decode an exact
  inverse.
- No multi-vendor dispatch was run this pass. Vendor CLIs were not exercised;
  `vendor_review.py`'s HEAD-mutation guard was therefore never involved.

### Observations

**Old PRs conflict over generated artifacts, not code.** #353, #408, #411 and
#422 all contend over the same seven `docs/architecture-analysis/*.json` files,
because each ran a refresh and committed the output. Their conflicts are
mechanical — regenerate, don't merge — and they will keep re-conflicting with
each other and with every convergence commit until rebased. The same held for
#364, whose entire conflict was main rewrapping YAML while the PR appended an
item: identical sentences, different column width.

**Two rebases were not mechanical.** #350's conflict was architectural: main had
independently implemented the same idea in `80ef32f1` while the PR sat open.
Resolving it needed a decision, not a merge — main writes the spec delta to
`specs/<change_id>/`, but every real change under `openspec/changes/` names that
directory after a *capability* (`architecture-refresh`, `roadmap-orchestration`,
`skill-workflow`) and one change may span several. Main's version was wrong; the
PR's `_capability_for` was right, and three of main's tests were corrected
because they asserted a convention the repository does not follow.

**A guard caught a defect in a sibling script.** `merge_pr.py` refused to merge
#442 with `"reason": "detached_head"` — my own staleness loop had left the shared
checkout detached, because `check_staleness.py` checks out PR heads and never
restores. Same class as #349 for `vendor_review.py`, but without that script's
snapshot/restore guard. Filed as #453. The layered guard did its job; the bug is
that it had to.

**The archive gate earned its keep.** `openspec archive` aborting rather than
dropping three scenarios is the single most valuable thing that happened in the
cleanup phase. A `--yes` flag that still refuses destructive spec loss is the
right default.

**Nine PRs remain open**, seven of them CONFLICTING and 6–38 days old. The
backlog is not shrinking on its own, and the generated-artifact contention means
it gets more expensive to clear the longer it sits.
