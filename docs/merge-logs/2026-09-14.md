### Observations
- **Executor deadlock on chained nodes (fixed in #544).** `merge_pr.refresh_branch` did not recognise the Update Branch API's 422 `There are no new commits on the base branch.` as up to date. `execute_plan` keeps `needs_revalidation=true` on a failed refresh and retries the refresh every time, so any node flagged by an upstream merge could never merge after its first refresh. The existing test mocked merge-upstream's wording ("not behind"), which is why it stayed green. #520 and #524 were merged through `merge_pr.py merge` (same CI/conflict/mergeability gates) once the 422 had shown each branch current on main.
- **Stale-merge heuristic false positive.** `docker-smoke-import` failed identically on 10 unrelated dependabot PRs while main was green. Step 5b would call that a stale merge base, but the logs show a PR-specific cause (lockfile out of date). "Same failure on 3+ PRs" needs the "failing files not in the PR" half of the rule checked against the log, not assumed.
- **`mergeable: UNKNOWN` after every merge.** GitHub computes mergeability lazily, so the first gate call after main moves is always refused; one `gh pr view` poke plus a retry resolved it every time.
- **Lockfile chains serialize.** The 5 kanban-viz PRs all touch `package-lock.json`; rebasing all at once would only re-conflict. They were rebased one at a time in plan order.
- **Classifier gap.** #484 touches only `openspec/changes/add-visual-code-explainer/` but sits on a `claude/*` branch, so `change_id_from_pr()` returns `None` and it is classified `implementation`/`quick-task` instead of `plan`/`iterate-on-plan`.
- **Convergence sweep hazard.** `main_convergence.py` runs `git add -A` when the refresh is sweepable. An unrelated untracked file (`tests/test_architecture/test_end_to_end_dispatch.py`) was parked outside the tree for the run and restored afterwards so it was not committed to main.
