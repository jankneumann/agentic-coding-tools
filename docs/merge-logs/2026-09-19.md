### Why this existed
Operator asked for the coordinator lock fix (#589). Its CI came back with `dependency-audit-skills` and `dependency-audit-coordinator` failing — on a diff that touches no dependency. Two advisories had been published for `anyio`, both fixed in 4.14.2:

- **CVE-2026-63374** — IDNA 2003/2008 mismatch in `connect_tcp()`/`TLSStream.wrap()`: a certificate legitimately issued for the 2003 encoding validates on a client connecting to the 2008 form.
- **CVE-2026-64847** — process-pool workers get stderr on an undrained pipe, against documented behavior; enough output wedges the awaiting call.

`anyio` is transitive (no pyproject declares it), so the fix was a targeted relock: skills 4.13.0 → 4.15.1, agent-coordinator 4.12.1 → 4.14.2/4.15.1, gen-eval 4.13.0 → 4.15.1. code-search and agent-scenarios were already at 4.14.2.

### The first attempt shipped a lockfile only my uv could read
`uv lock --upgrade-package anyio` in gen-eval produced a lock that `uv lock --check` accepted locally (uv 0.12.7) and CI refused outright:

```
error: Failed to parse `uv.lock`
  cause: Dependency `typing-extensions` has missing `source` field but has
         more than one matching package
```

Upgrading anyio had split `typing-extensions` into two marker-scoped blocks (4.15.0 for py ≥ 3.15, 4.16.0 below) where main had one, and a dependency reference to it carries no `source` to disambiguate. `gen-eval-tests` and `requirement-traceability-sweep` both failed before running a single test. Upgrading `typing-extensions` alongside anyio collapsed it to one block at 4.16.0.

`agent-coordinator` also gained a split — of anyio itself (4.14.2 below py 3.15, 4.15.1 above). That one parses (`dependency-audit-coordinator` passed on the same run) and both versions are patched, so it stands.

### Observations
- **A green local lock gate is not a green CI lock gate.** `uv lock --check` passed on a lockfile CI could not parse at all. The check validates that the lock matches the pyproject, not that every dependency reference is unambiguous — and the two uv versions disagreed about the latter. Any relock now warrants a mechanical check for newly split packages, not just a `--check`.
